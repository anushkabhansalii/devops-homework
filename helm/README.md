## What Helm is
Helm is the **package manager for Kubernetes**. Instead of keeping one copy of every YAML per environment, you write a **chart** (YAML templates with `{{ }}` placeholders) once and feed it different **values**.

| Term | Meaning | Analogy |
|---|---|---|
| **Chart** | package of templated K8s manifests + `Chart.yaml` + `values.yaml` | recipe |
| **Values** | variables that fill the templates (`values.yaml`, `-f file`, `--set key=val`) | ingredients |
| **Release** | one installed instance of a chart in a cluster (e.g. `web`, `shop`, `notes-dev`) | the cooked meal |
| **Revision** | every install/upgrade/rollback of a release gets a new number, stored as a Secret in the namespace | version history |
| **Repository** | an HTTP index of packaged charts (`helm repo add`) | app store |

Helm 3+ is client-only (Helm 2's in-cluster *Tiller* with cluster-admin rights is gone); release state lives in Secrets in the release's namespace. Value precedence: chart `values.yaml` < `-f custom.yaml` < `--set`.

| Command | What it does |
|---|---|
| `helm create <name>` | scaffold a new chart |
| `helm lint <chart>` | check a chart for errors |
| `helm template <rel> <chart>` | render YAML locally, no cluster |
| `helm install <rel> <chart>` | create a release (revision 1) |
| `helm list [-A]` | list releases |
| `helm status <rel>` | release status + its resources |
| `helm get values/manifest/notes <rel>` | read what's stored in a release |
| `helm upgrade <rel> <chart>` | new revision with new chart/values (`--install` to create if missing) |
| `helm history <rel>` | all revisions |
| `helm rollback <rel> <rev>` | re-apply an old revision as a new one |
| `helm uninstall <rel>` | delete the release and its resources |
| `helm repo add/update/list/remove` | manage chart repositories |
| `helm search repo/hub <term>` | find charts locally / on Artifact Hub |

## Task 2: Complete rollback workflow
**Install → Upgrade → Verify → Upgrade again → Verify → Rollback → Verify**, on release `shop`.

**1. Install** (revision 1, nginx 1.26, 1 replica)
```text
$ helm install shop ./myapp --set image.tag=1.26
STATUS: deployed
REVISION: 1
$ kubectl get deploy shop-myapp -o jsonpath=...
1 replicas, image nginx:1.26
```
**2. Upgrade → 3. Verify** (revision 2, nginx 1.27, 3 replicas)
```text
$ helm upgrade shop ./myapp --set image.tag=1.27 --set replicaCount=3
REVISION: 2
$ kubectl get pods -l app.kubernetes.io/instance=shop
shop-myapp-59b9d469b8-bjn6k   1/1     Running       0          3s
shop-myapp-59b9d469b8-hd55m   1/1     Running       0          4s
shop-myapp-59b9d469b8-zjkwj   1/1     Running       0          2s
$ kubectl get deploy shop-myapp -o jsonpath=...
3 replicas, image nginx:1.27
```
**4. Upgrade again → 5. Verify** (revision 3, a **bad image tag**, simulating a broken release)
```text
$ helm upgrade shop ./myapp --set image.tag=9.99-does-not-exist --set replicaCount=3
Release "shop" has been upgraded. Happy Helming!
STATUS: deployed
REVISION: 3

$ kubectl get pods -l app.kubernetes.io/instance=shop
NAME                          READY   STATUS         RESTARTS   AGE
shop-myapp-59b9d469b8-bjn6k   1/1     Running        0          26s
shop-myapp-59b9d469b8-hd55m   1/1     Running        0          27s
shop-myapp-59b9d469b8-zjkwj   1/1     Running        0          25s
shop-myapp-65c789b8cc-r7ws6   0/1     ErrImagePull   0          9s     <- new revision is broken

$ helm history shop
REVISION	STATUS    	DESCRIPTION
1       	superseded	Install complete
2       	superseded	Upgrade complete
3       	deployed  	Upgrade complete       <- Helm thinks it's fine!
```
Two lessons here:
- Helm said `deployed` — without `--wait` (or `--atomic` / Helm 4's `--rollback-on-failure`) it only checks that the API server **accepted** the manifests, not that pods became healthy. Verifying with `kubectl` is essential.
- There was **no outage**: the Deployment's rolling update created 1 new pod first, it never became Ready, so the 3 old `nginx:1.27` pods were never removed.

**6. Rollback → 7. Verify**
```text
$ helm rollback shop 2
Rollback was a success! Happy Helming!

$ kubectl get deploy shop-myapp -o jsonpath=...
3 replicas, image nginx:1.27

$ kubectl get pods -l app.kubernetes.io/instance=shop
shop-myapp-59b9d469b8-bjn6k   1/1     Running       0          26s
shop-myapp-59b9d469b8-hd55m   1/1     Running       0          27s
shop-myapp-59b9d469b8-zjkwj   1/1     Running       0          25s
shop-myapp-65c789b8cc-r7ws6   0/1     Terminating   0          9s     <- broken pod removed

$ helm history shop
REVISION	STATUS    	DESCRIPTION
1       	superseded	Install complete
2       	superseded	Upgrade complete
3       	superseded	Upgrade complete
4       	deployed  	Rollback to 2
```
Back to the known-good config (revision 2's values) in seconds, and the history keeps a full audit trail of what happened.

## Task 3: Mini project — Notes App chart
Chart: [`mini-project/notes-chart/`](./mini-project/notes-chart) — a ConfigMap (`APP_NAME`, `ENVIRONMENT`), a Deployment that loads it with `envFrom`, and a NodePort Service. Every name is built from `{{ .Release.Name }}` so the same chart can be installed many times.

| | `values.yaml` (dev) | `values-prod.yaml` (prod) |
|---|---|---|
| replicaCount | 1 | 3 |
| image | nginx:1.24 | nginx:1.25 |
| app.environment | development | production |

**Lint + render**
```text
$ helm lint notes-chart
1 chart(s) linted, 0 chart(s) failed

$ helm template notes-dev notes-chart
# Source: notes-chart/templates/configmap.yaml
kind: ConfigMap
metadata:
  name: notes-dev-config
data:
  APP_NAME: "notes-app"
  ENVIRONMENT: "development"
# Source: notes-chart/templates/deployment.yaml
...
          image: "nginx:1.24"
          envFrom:
            - configMapRef:
                name: notes-dev-config
```
**Install (development)**
```text
$ helm install notes-dev notes-chart
STATUS: deployed
REVISION: 1

$ kubectl get deploy,pods,svc,configmap | grep -E 'NAME|notes-dev'

service/notes-dev-svc   NodePort    10.100.187.224   <none>        80:30090/TCP   29s
```

**Upgrade to production values**

### A chart from Artifact Hub: install, list, uninstall, repo remove
```text
$ helm repo add bitnami https://charts.bitnami.com/bitnami --force-update
$ helm repo update bitnami
$ helm install my-nginx bitnami/nginx --set service.type=ClusterIP

CHART VERSION: 25.2.1
$ helm list
my-nginx	default	1	deployed	nginx-25.2.1	1.31.6
$ helm uninstall my-nginx

$ helm repo remove bitnami

```
Like `docker pull` but for a whole application: Helm downloaded the chart (Deployment, Service, ...) and installed it as one release.

### `helm lint` catches a typo before deploying
```text
$ helm lint simple-chart
1 chart(s) linted, 0 chart(s) failed
# broke the indentation of `replicas:` in templates/deployment.yaml
$ helm lint /tmp/lint-demo
[ERROR] templates/deployment.yaml: unable to parse YAML: error converting YAML to JSON: yaml: line 7: mapping values are not allowed in this context
Error: 1 chart(s) linted, 1 chart(s) failed
```
Order to follow for any custom chart: **`helm lint` → `helm template` (dry run) → `helm install`**.

### `install` vs `upgrade` vs `upgrade --install`
```text
$ helm upgrade my-app simple-chart
Error: UPGRADE FAILED: "my-app" has no deployed releases          <- upgrade needs an existing release
$ helm upgrade --install my-app simple-chart
STATUS: deployed   REVISION: 1                                     <- creates it if missing
$ helm upgrade --install my-app simple-chart --set replicaCount=3
STATUS: deployed   REVISION: 2                                     <- upgrades it if present
$ helm install my-app simple-chart
Error: INSTALLATION FAILED: ... cannot reuse a name that is still in use   <- install only creates
```
| Command | Release missing | Release exists |
|---|---|---|
| `helm install` | creates (rev 1) | **error** (like `kubectl create`) |
| `helm upgrade` | **error** | new revision (like `kubectl apply`) |
| `helm upgrade --install` | creates | new revision — what CI/CD pipelines use |
| `helm uninstall` | error | deletes release + objects + history |

`--set replicaCount=3` overrides a value at deploy time; doing that by hand instead of in a values file creates **drift** between Git and what is running.
